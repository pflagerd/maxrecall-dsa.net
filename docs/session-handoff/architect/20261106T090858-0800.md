## How we work (architect)

- **Commit a handoff on a branch started from `origin/master`** (as
  questions' handoff describes), never on a branch with unmerged work:
  `git push origin HEAD:master` pushes every commit the branch has. This
  one went that way, on `architect-handoff-tmp`, deleted after.
- **After a merge, restart the branch at `master`**, so new work never
  stacks on a merged pull request. **Corrected** (questions' handoff
  `20261106T090604-0800.md`): the last two handoffs said `git checkout
  -B <branch> origin/master` then a plain `git push`. That doesn't push:
  `checkout -B` from `origin/master` makes `origin/master` the branch's
  upstream (`branch.autoSetupMerge`, default `true`), and a plain push
  under `push.default=simple` (the default) refuses an upstream named
  differently ("The upstream branch of your current branch does not
  match the name of your current branch"; reproduced in a scratch
  repository, git 2.43.0). The architect's restarts worked only because
  it ran `git push origin <branch>`, naming the branch. Use either:
  - `git merge --ff-only origin/master`, then `git push` (works for a
    merged branch, whose tip is in `master`'s history; the upstream is
    left alone). Recommended: one less thing to get wrong.
  - `git checkout -B <branch> origin/master`, then `git push -u origin
    <branch>`: `-u` sets the upstream back to `origin/<branch>`.

  Then check with `git ls-remote origin refs/heads/<branch>`; and
  `git status -sb` shows the upstream (`<branch>...origin/master` means
  it's wrong).
- **Check a role's claim about another role's code against the code**:
  "`questionInfos()` doesn't pass it on, so users' code is unaffected"
  was half right; `toPublicProblem` was the other path.
- **Ref names with `/` break `sed s/…/…/`**: `origin/master` did, which
  gave an empty list and a false "77 removed". Use `s|…|…|`, and
  distrust a diff that says everything changed.
- From before, still true: `git fetch --unshallow origin` before
  comparing branches; judge ownership by the rules in force at the
  commit's time; retry a push that GitHub refuses (`commit_refs`); edits
  by script assert each replacement matches once; contracts name
  identifiers, not line numbers (this file's line numbers are a
  snapshot), and search strings, paths and globals a `require` scan
  can't see.
