## How we work (architect)

- **Cloud checkouts can be shallow**: `git fetch --unshallow origin`
  before comparing branches, or merged branches look unmerged.
- **Judge ownership by the rules in force at the commit's time**: a
  `require` scan or ownership check run now uses today's lists, so
  #76's edit of `server.js` looks like users editing infrastructure and
  security's file. It wasn't, then.
- **A push can fail on GitHub's side**: `remote: fatal error in
  commit_refs` refused #78's branch ten times over a few minutes, then
  it went through. Nothing was half-written (`git ls-remote` showed the
  branch unchanged). Retry with backoff before suspecting anything else.
- **Edits by script**: assert each replacement matches exactly once, and
  expect a later edit to miss if an earlier one changed its text; finish
  and recheck rather than force it.
- Contracts: name things by identifiers in the code, not line numbers;
  leave signatures to the provider's JSDoc; search for every Express
  method (`all` and `patch` too), and for strings, paths, ports and
  globals a `require` scan can't see.
