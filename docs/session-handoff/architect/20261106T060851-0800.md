## Later: UTC (owner: "migrate everything to UTC eventually. Leave it alone for now.")

When handoff names change from `-0800` to `Z`, a UTC name sorts 8 hours
(7 in daylight saving time) later than a Pacific one for the same moment.
So "the newest is the last by name" (`CLAUDE.md`) can pick the wrong file
around the switch unless the old names are renamed, or the first UTC one
is written at least that long after the last Pacific one. The readme's
Decisions rows and several roles' docs are already dated by UTC.

## How we work (architect)

- **Commit a handoff on a branch started from `origin/master`** (as
  questions' handoff describes), never on a branch with unmerged work:
  `git push origin HEAD:master` pushes every commit the branch has. This
  one went that way, on `architect-handoff-tmp`, deleted after.
- **Check a role's claim about another role's code against the code**:
  "`questionInfos()` doesn't pass it on, so users' code is unaffected"
  was half right; `toPublicProblem` was the other path.
- **Ref names with `/` break `sed s/…/…/`**: `origin/master` did, which
  gave an empty list and a false "77 removed". Use `s|…|…|`, and
  distrust a diff that says everything changed.
- From before, still true: `git fetch --unshallow origin` before
  comparing branches; judge ownership by the rules in force at the
  commit's time; retry a push that GitHub refuses (`commit_refs`); edits
  by script assert each replacement matches once; contracts name
  identifiers, not line numbers (this file's line numbers are a
  snapshot), and search strings, paths and globals a `require` scan
  can't see.
