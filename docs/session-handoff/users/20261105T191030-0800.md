## How we work (this session's additions)

- **A copy of the VPS in a cloud container**, to try VPS procedures
  first. As root: `adduser --system --group --home /srv/maxrecall --shell
  /usr/sbin/nologin maxrecall` (as `scripts/deploy-server.sh`); `git
  clone` the repository into `/srv/maxrecall/maxrecall-dsa.net` **at the
  commit wanted** (the container's local `master` can be days old:
  clone the session's branch, or check the start-up log against current
  code); copy `node_modules` in; `chown -R maxrecall:maxrecall`;
  `data/users` as `maxrecall`, `install -d … data/archive`; then start
  the server as `maxrecall` with the service file's `Environment=` lines
  plus `MAXRECALL_UNSANDBOXED=1` (cloud only), under `setsid nohup` so it
  outlives the command. Then run a page's commands verbatim. Not in the
  copy: nginx, systemd, the sandbox, SSH to the VPS.
- **Browser checks in the cloud**: cdnjs is blocked; serve CodeMirror
  5.65.16 and KaTeX 0.16.9 from an npm install in the scratchpad through
  Playwright's `context.route`. A new browser context is a private
  window. Playwright never counts an `<option>` as visible: wait for it
  with `{ state: 'attached' }`.
- **`hidden` and CSS**: any rule that sets `display` on an element beats
  the browser's `[hidden] { display: none }`. To check a page, set
  `hidden` on each element its script hides and read
  `getComputedStyle(el).display`.
- **Editing a service-owned file by hand**: `SUDO_EDITOR=vi sudoedit -u
  maxrecall <file>` edits a copy and writes it back as `maxrecall`; `vi`
  as root may leave it root's.
- **Before telling the owner a check passed, check the test's
  assumptions**: this session called the copy's owner profile "every
  language allowed" when `make learner-create` had written `allowed:
  python`, so that check proved nothing until redone.
