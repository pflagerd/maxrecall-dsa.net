## How we work (this session's additions)

- **One gate before every commit and push**: `git fetch origin master`;
  stop if `master` moved and merge it in (never rebase a pushed branch);
  `git merge-tree --write-tree --name-only HEAD origin/master` must exit
  0; only then commit, and `git push` as its own call, after the gate's
  result is read. A command that prints the new hash doesn't stop on it:
  compare it with the expected one (`[ "$(git rev-parse --short
  origin/master)" = "<expected>" ]`).
- **After a pull request merges**: `git checkout -B <branch>
  origin/master`, then `git branch -u origin/<branch>`, since `-B` from
  `origin/master` makes `master` the upstream; `git push` is then a
  fast-forward.
- **A check that runs code at start-up**: wait for the last thing
  start-up prints, not for the server to listen. `async` work finishes
  after it.
- **Moving code without changing it**: cut at text markers, each asserted
  to occur once, then compare the old file's lines with the new files'
  as multisets (sorted, counted) to list exactly what was added and
  removed. Infrastructure and security used the same comparison to
  review.
- **Checking a file `make doc-check` or `make typecheck` doesn't list**:
  copy `scripts/doc-check.js` into a scratch folder with a
  `tsconfig.json` listing only that file and a link to `node_modules`.
- **A type import across files** (`import('./server').AppRequest`):
  confirm it isn't silently `any` by adding a deliberate type error in a
  copy and seeing `tsc` reject it.
- Cloud containers may lack `node_modules` (`make install`) and
  bubblewrap (judging needs `MAXRECALL_UNSANDBOXED=1`, cloud only). This
  repository has no CI: a pull request's checks are the ones run by hand.
- This repository is public: nothing about other repositories'
  weaknesses or the VPS's addresses in files here.
