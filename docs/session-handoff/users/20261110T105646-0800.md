## Lessons, for whoever works on the learner's files

- **Check what a condition means on the live machine** before proposing
  a rule on it: "`MAXRECALL_USERS_DIR` is set" was true on the VPS for
  real data. `deploy/maxrecallcode.service` and `docs/deploy-vps.md`
  answer such questions.
- **Re-read an issue's own plan before recommending**: issues here
  change after they're first read.
- **Break a check on purpose** to see its test fail. It caught a test
  that passed for the wrong reason.
- **Look names and numbers up in git**, don't write them from memory.
- **`make characterize` records keys and value types only**: for a
  refactor meant to change nothing, compare full response bodies too.
- **The problem page can be checked in a cloud browser**:
  `cdnjs.cloudflare.com` is blocked, so serve CodeMirror and KaTeX from
  `npm pack` copies of the same versions through Playwright's
  `page.route`; use a test bank (`MAXRECALL_QUESTIONS_DIR` and a
  `TEST-USERS` users folder) for questions not in the repo.
- **This container had no `bwrap` and no `node_modules` at start**
  (`command -v bwrap` printed nothing), as infrastructure and security
  found: with two repositories attached, the session starts in
  `/home/user` and the repository's SessionStart hook doesn't run.
  `make test` doesn't need the sandbox; `make dev` and `make run`
  install it themselves. The open question (three options) is in
  `infrastructure-and-security/20261110T105129-0800.md`, now core's.
- **After a rebase of a branch with no pull request**,
  `git push --force-with-lease=<branch>:<sha>` went through where a bare
  `--force-with-lease` was refused.
