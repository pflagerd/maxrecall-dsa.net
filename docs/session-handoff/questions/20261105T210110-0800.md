## How we work

- **The gate before every commit and push**: `git fetch origin master`;
  if `master` moved, merge it in (never rebase a pushed branch); `git
  merge-tree --write-tree --name-only HEAD origin/master` must exit 0;
  commit; `git push` as its own call. After a merge, `git merge
  --ff-only origin/master` and a plain `git push` restart the branch.
- **Edit question files as raw text**: exact replacements in a short
  Python script in the scratchpad, each asserted to match once, run with
  `python3 -I`. Re-saving parsed JSON reformats the whole file.
- **Run every claim before it goes in a question.** All five toolchains
  are in the cloud: `javac`/`java`, `g++ -std=c++17`, `ldc2`, `node`,
  `python3`. To judge solutions through the real judge, call
  `runSubmission` from a scratch script with `MAXRECALL_UNSANDBOXED=1`
  (cloud only, never the VPS), as `judge/line-numbers-test.js` does.
- **Check what you write about the files with a script over them.** Three
  of the guide's first claims were wrong until checked that way, and a
  remembered time (19:50) was really 19:59.
- **Break each new check on purpose**, and see a test fail.
- **cppreference.com and dlang.org are unreachable** from this
  environment, including through a web-fetch agent; say so rather than
  guess.
- `git fetch --unshallow origin` before comparing branches.
