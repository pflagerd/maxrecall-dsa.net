## How we work

- **The gate before every commit and push**: `git fetch origin master`;
  if `master` moved, merge it in (never rebase a pushed branch); `git
  merge-tree --write-tree --name-only HEAD origin/master` must exit 0;
  commit; `git push` as its own call. After a merge, `git merge
  --ff-only origin/master` and a plain `git push` restart the branch.
- **Edit question files as raw text**: exact replacements in a short
  Python script in the scratchpad, each asserted to match once, run with
  `python3 -I`. Re-saving parsed JSON reformats the whole file. A script
  that writes each file only after all its replacements match leaves
  nothing half-done when one misses.
- **Write a new question with a generator script** (this session's were
  in the scratchpad, now gone): build the dict, then write it with short
  lists inline and one test case per line, like the other files. Check
  it reproduces the file byte for byte before editing it, so a rewrite's
  diff shows only what changed.
- **Run every claim before it goes in a question.**
  - All five toolchains are in the cloud: `javac`/`java`,
    `g++ -std=c++17`, `ldc2`, `node`, `python3`.
  - To judge solutions through the real judge, call `runSubmission` from
    a scratch script with `MAXRECALL_UNSANDBOXED=1` (cloud only, never
    the VPS), as `judge/line-numbers-test.js` does. Judge a wrong solution
    too.
- **Check what you write about the files with a script over them**, and
  remembered times with `git log`: several first claims this session were
  wrong until checked.
- **Break each new check on purpose**, and see a test fail.
- **Read a change in place before committing**: a warning that read well
  on its own gave the answer away once it sat in the page (#86).
- **External documentation sites are unreachable here**; say a link is
  unchecked rather than guess, and list it in the pull request.
- `git fetch --unshallow origin` before comparing branches.
