## Lessons

- **Run the owner's wording before it goes in a template** (`\.`).
- **A new required field breaks another role's fixtures**: core's
  `routes.test.js` checks its test questions with `checkQuestion`, so
  the format change and core's had to merge together (core's pull
  request built on my commit). Say so in the plan first.
- **A catch-all message may claim only what's true of every answer that
  reaches it.** Mine said "unterminated string literal" for all; `'x`
  and `'*2` showed otherwise. `trim()` is the same trap.
- **Read a checker's alarm against the raw output**: my own script
  raised two false alarms.
- **Take every file name from a listing**: I wrote a decision file's
  timestamp from memory in a handoff, wrongly, the mistake
  yesterday's handoff warned of. Corrected in a second commit.
- **Messages between sessions**: to the architect, refused every time
  ("needs proof of a trusted device"), even at the owner's word; to
  core, delivered twice then refused; to questions-1, delivered. All
  three could message me. `list_events` on core's session was refused.
  So every request goes in the pull request's or issue's description,
  and the owner asks the architect for an R3 review.
- **A draft can be reviewed**: say so when holding a pull request for
  R3, and that it's a draft only so it can't be merged first.
- **A fix after R3 needs R3 again**: take a non-blocking observation up
  in a later pull request.
- **A handoff while a pull request is open** is committed on a branch
  made from `origin/master`, since the session's branch then holds
  more than a handoff.
