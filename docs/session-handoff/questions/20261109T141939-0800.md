## Learned

- **A shallow clone gives false alarms**: `git fetch` reported a "forced
  update" of `master`, and `git merge-tree` "refusing to merge unrelated
  histories", because the shared commit wasn't downloaded. After
  `git fetch --unshallow origin` both were fine. Unshallow before
  trusting either message in a cloud session.
- **Two sessions of one role share this folder, and file names are to
  the second**: questions 2's handoff and my first try at this one were
  both `20261109T141909-0800.md` (an add/add conflict on rebase). Take
  the timestamp just before committing, and check the name is free on
  the fetched `master`. Questions 2's record of the split is that file.
