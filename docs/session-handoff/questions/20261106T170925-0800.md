## Found: users' `routes.test.js` depends on three question files

Users' `routes.test.js` (#106, in `make test` since then) judges real
code through a real `node server.js`, so it relies on questions' files
in ways `docs/contracts.md` doesn't record. Contract 4 names fields and
functions, not particular questions. Read from the test at `783d0f0`:

- **`questions/two-sum.json`** (function mode): exists; Python's
  `functionName` is `two_sum` and JavaScript's `twoSum`; a hash-map
  solution (`TWO_SUM_PY`, `TWO_SUM_JS`) is Accepted in both; `return [0,
  0]` (`WRONG_PY`) is Wrong Answer. Run, Test, Submit and Skip are all
  tested on it.
- **`questions/hello-world.json`**: exists, in Python and JavaScript
  (a chosen backlog of it; "every question, in each allowed language").
- **`questions/valid-parentheses.json`**: exists, in Python (Skip).
- Also relied on: the status strings `Accepted` and `Wrong Answer`
  (`judge/runner.js`, questions'; contract 2), and the Test button's
  answer: `tested`, `total`, `results` (`playtest.js`; contract 3).

**Checked by breaking it**: with `two-sum.json`'s Python `functionName`
changed to `two_sum_renamed`, `node --test routes.test.js` gave 20 pass,
3 fail (Run, Submit, Skip); the file was restored after. So renaming,
deleting, or changing what these three return or are called, breaks
users' test, though nothing in their code is wrong.

Also, by hand only: `scripts/characterize.js` snapshots
`/api/questions/two-sum` and `/hello-world` before and after a refactor
(users', #106). Any edit to those two between the snapshots shows as a
difference that isn't the refactor's.

**Until the contract says so, questions treats these three as fixed**:
no rename, deletion, `functionName` change or change to what's judged
right, without first agreeing it with users (through the architect).
Wording, Learning tabs and added test cases that the two solutions
still pass are fine, as far as I can read the test; run
`node --test routes.test.js` after any edit to them to be sure.
