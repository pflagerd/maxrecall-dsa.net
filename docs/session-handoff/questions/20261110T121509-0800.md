## Learned

- **A required field breaks another role's fixtures.** Core's
  `routes.test.js` runs its own test questions through `checkQuestion`,
  so a new required field in the format fails `make test` there, and the
  two changes can't merge one after the other. What worked: my pull
  request as a draft saying why, core's built on top of my commit and
  carrying both; the owner merged core's. Next time, say so in the plan
  before building.
- **`send_message` isn't steady.** To core: delivered twice, then
  refused ("needs proof of a trusted device"). To the architect: always
  refused. Both could message me throughout, and both found PR 237's
  requests from its description by polling. So put every request in the
  pull request's description, not only in a message.
- **`list_events` on core's session was refused too**: I couldn't check
  the owner's words relayed from there, and asked the owner here.
- **Titles end with the session's name** from today (PR 236):
  "(questions-2)", not "(questions)".
- **Handoffs while a pull request is open**: the session's branch then
  holds more than a handoff, so the handoff is committed on a branch
  made from `origin/master` and pushed from there.
