## Request: architect (4b, owner's choice: a scheduled GitHub Actions check)

**Please add `.github/workflows/` to infrastructure and security's
ownership list.** It isn't in any role's list, and `.github/` doesn't
exist yet. A workflow is code that GitHub runs with a token, so a
security role's. The workflow is written once it's assigned.

Its design, from GitHub's docs (fetched 2026-11-07):

- Every 15 minutes, **not on the hour**: "The schedule event can be
  delayed during periods of high loads … High load times include the
  start of every hour … some queued jobs may be dropped". The minimum is
  "once every 5 minutes", and it runs on the default branch only
  ([events that trigger workflows, `schedule`](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)).
- One step: `curl -fsS -o /dev/null https://maxrecallcode.net/login.html`.
  `/login.html` is one of the app's `PUBLIC_PATHS` (`server.js`), and
  nginx passes every path to port 3000, so a `200` means the app answers.
  When it's down, nginx gives `502`, and `curl -f` fails.
- `permissions: {}`: the token gets nothing (workflow syntax,
  `permissions`). No third-party actions, so nothing to pin.
- Also `workflow_dispatch`, so the owner can run it by hand.
- Free: "Standard GitHub-hosted runners in public repositories … remains
  free" ([billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)).

**Two things the owner must do, from the docs:**

1. **Turn on notifications for Actions.** Email isn't automatic: "If you
   enable email or web notifications for GitHub Actions, you'll receive a
   notification …", optionally for failed runs only
   ([notifications for workflow runs](https://docs.github.com/en/actions/concepts/workflows-and-actions/notifications-for-workflow-runs)).
2. **Disable and re-enable the workflow once**, in the Actions tab, after
   it's merged. Scheduled workflows notify "the user who initially
   created the workflow". This role's commits are authored as `Claude
   <noreply@anthropic.com>`, which is no GitHub user, so who that is
   isn't clear. But "If a scheduled workflow is disabled and then
   re-enabled, notifications will be sent to the user who re-enabled the
   workflow". That makes it the owner, for certain.

Known limit: "In a public repository, scheduled workflows are
automatically disabled when no repository activity has occurred in 60
days" (same page). So a quiet repository loses its check silently.
