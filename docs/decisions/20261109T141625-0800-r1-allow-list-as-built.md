# R1's allow-list of names, as built: a built-in is only called or read from; scope by TypeScript's checker

2026-11-09 (UTC; the same day Pacific) · decided by the owner (the allow-list, option (a)); the choices marked below by questions 2, building it · written by questions (questions 2)

**Decided** (owner, 2026-11-09, option (a): #160's comment of that day;
`docs/decisions/20261109T135112-0800-r1-closed-by-kind-its-limit-stated-allow-list-next.md`):
a judge file refers only to names it declares or to a short allow-list of
built-ins (`String`, `Number`, `Boolean`, `Math`, `JSON`, `Array`, `Set`,
`Map`, `RegExp`, `undefined`, `NaN`, `Infinity`); no writes to a
built-in; no `prototype`; no `async`, `await` or generators.

**Choices made building it** (questions 2, stated to the owner before
building; `questions.test.js`, `judgeSourceProblems`):

- **A built-in object is only called or read from, never a value.** It
  may be `String(x)`, `new Set()`, `Math.max(a, b)` or `Math["PI"]`. It may
  not be `const M = Math`, `arr.map(Number)` or `x instanceof Array`.
  - Why: the write rule looks at the name a write starts from. With
    `const M = Math; M.max = () => 0;` that name is the judge's own `M`.
    Run on Node 22.23.4, loading that judge set `Math.max(1, 2)` to `0`
    for the whole process.
  - `undefined`, `NaN` and `Infinity` aren't objects, so they may be used
    anywhere.
- **`RegExp` is only called or constructed**, never read from (the
  architect's R3 review of #191). Its legacy statics (`RegExp.input`,
  `lastMatch`, `$1`–`$9`, `leftContext`, `rightContext`) hold the last
  match made anywhere in the process. Run on Node 22.23.4: after a token
  was tested against a pattern, a judge's message carried that token.
  `auth.js` tests session tokens that way (`auth.js:503`). Of the allowed
  built-ins, only `RegExp` has such properties: the others' own
  properties are all functions or fixed constants (listed with
  `Object.getOwnPropertyNames`). Regex literals (`/x/`) need no name, so
  they're unaffected.
- **A write's target** is a variable the judge declares, a property of
  one (`o.x`, `o.x.y`), or `module.exports` and its properties.
  Destructuring targets and `for (x.y of …)` are checked one by one.
  A write starting anywhere else (`[].x = 1`, `f().x = 1`) is refused.
- **Scope comes from TypeScript's checker.** The check builds a program
  of the one file, with no lib, and asks the checker what each name
  refers to. So `function f(fetch) { return fetch; }` is the judge's own
  `fetch`, and a `fetch` outside it is the global, which is refused.
  - Only a real declaration counts: a variable, parameter, function,
    class, destructuring name or catch binding. In a JavaScript file
    TypeScript also treats `Math.max = …` as declaring `Math` (its
    "expando" assignments). Without this rule, that write passed.
- **The deny-lists stay.** A name in `JUDGE_FORBIDDEN_NAMES` is refused
  even if the judge declares it. The messages say why, as before.

**What it still can't do**: the same as R1 says (`docs/roles/questions.md`,
"Judge files"). It reads a judge's text, so it catches accidents, not
every deliberate evasion. Review (R3) is the guard against those; #185
would be the boundary.
