# R1: a judge file makes no property writes at all

2026-11-09 (UTC; the same day Pacific) · decided by the owner ("Yes, go with (i).", in the architect's session) · written by questions (questions 2)

**Background.** #191 built R1's allow-list, which allowed writes to the
judge's own variables, their properties, and `module.exports`. The
architect's R3 re-review of #191 and questions 2 found the residual that
left open. All of these were run on Node 22.23.4, and each passed the
check:
- `const h = ({}).hasOwnProperty; h.call = () => true;` made
  `Object.prototype.hasOwnProperty.call(…)` return `true` for the whole
  process. Express's dependency `proxy-addr` uses that idiom
  (`node_modules/proxy-addr/index.js:102`).
- `module.exports = h; module.exports.call = …` did the same.
- `const p = [].push; p.apply = …` and
  `const f = Math.max; f.call = …` did the same for those methods.

**Decided** (owner, 2026-11-09, option (i), over leaving it to review
and #185): **no property writes at all.** A write's target is a
variable the judge file declares, or `module.exports` itself, exactly.
That applies to every form of write: `=`, compound assignment, `++`,
`--`, `delete`, and destructuring and `for (… of/in …)` targets. It
covers the judge's own objects too, since the check can't tell a
built-in function read into a variable from the judge's own object.

Method calls on the judge's own objects aren't writes and stay allowed
(`list.push(x)`, `map.set(k, v)`). Changing a built-in function without
a property write needs `Object.defineProperty` or `Reflect`, which R1
already makes unreachable. So this closes the kind.

**What it costs a judge**: it builds its verdict as an object literal
(`return { pass, message }`), and keeps state in variables, or in
arrays, `Map`s and `Set`s through their methods.
