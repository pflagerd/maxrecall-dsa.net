# Updates to the VPS are deployed with the guarded deploy

2026-11-08 · owner's request for the write-up · written by infrastructure and security

**Decided** (owner, 2026-11-08, asking this role for the write-up the VPS
operator requested; approved by merging): an update is deployed with the
**guarded deploy**, `docs/deploy-vps.md`, "The quick way", "Updating: the
guarded deploy". The owner says yes to one commit, by its id. As root in
root's checkout: `git fetch origin master`; only if `origin/master` is
that commit, `git merge --ff-only <commit> && make deploy-server`;
otherwise stop, list what's new, read every new handoff in full, and
ask the owner again with advice (owner, 2026-11-07). `make
deploy-server` reads from `/dev/null`, so an unexpected first-run
question stops it before anything changes. Afterwards, the service's checkout
must be at the same commit.

**Why**: `make deploy-server` deploys the tip of `master`, with no
pinning (owner, 2026-11-07). Without the guard, commits merged after the
owner's yes would go live unseen. The merge in root's checkout also
fixes which `Makefile` and `scripts/deploy-server.sh` run as root: those
of the commit approved. The steps before it check root's checkout is on
`master` with no uncommitted edits, since those would run as root too.

**What it can't close**: `scripts/deploy-server.sh` fetches `master`
again into `/srv/maxrecall/maxrecall-dsa.net`, seconds later. A merge in
those seconds goes live too. Step 5 compares the two commit ids and
catches it afterwards. Closing it beforehand would mean the script
refusing a tip other than the approved commit. That's a change to the
script, not proposed here.

**Checked** in throwaway repositories (a bare one as GitHub, root's and
the service's clones, a stand-in `make` that pulls as the script does):
master unchanged deploys; master moved stops with nothing deployed; an
unpushed commit in root's checkout stops at `--ff-only` before `make`; a
merge during the deploy is caught by step 5; a failed fetch stops.

Source: `scripts/deploy-server.sh` (the `git fetch`/`pull --ff-only` in
§4's block), `Makefile` (`deploy-server`), the VPS operator's handoff
`docs/session-handoff/vps-operator/20261107T092844-0800.md`.
