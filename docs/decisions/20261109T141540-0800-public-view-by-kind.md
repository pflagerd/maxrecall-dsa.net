# A question's public view is chosen by its kind, and always says the kind

2026-11-09 · proposed by users, decided by the owner's merge of the pull request that adds this file · written by users

#160's Q4 (owner, 2026-11-08) made each kind's public view users': an
allow-list in `routes.js`, within contract 4's never-sent fields, and "a
page that meets a kind it doesn't know says so, rather than showing a
broken editor". How that's built:

- **`kind` is sent with every question**, from `question-files.js`'s
  `kindOf()`, so a file without one says `"code"`. The page reads it to
  choose how to show the question, and doesn't need its own copy of the
  rule that an absent kind means code (#160's Q3, rule 1: one function).
  Every code question's answer gains `"kind": "code"`; nothing else in it
  changes.
- **Each kind's list starts from one common list** (`PUBLIC_COMMON_FIELDS`):
  `slug`, `title`, `difficulty`, `topics`, `sources`, `alreadyLearned`,
  `learning`, `description`.
- **A fill-in-the-blank question** sends `template` and `blank`, and
  `maxLength` with its default filled in by `fillInTheBlankMaxLength()`,
  so the page doesn't need to know the default either. Nothing of its
  judge, which is a file of its own.
- **A kind the server doesn't know** gets the common fields only, so the
  page can name the question and say it can't show it, and nothing
  kind-specific leaves the server.
- **The page shows only code questions so far**: for any other kind it
  shows the header and the message "This page can't show this kind of
  question yet (“<kind>”).", with the controls turned off, until the
  fill-in-the-blank page is built (#160 step 4).

**Why**: one place applies the kind's default; the page gets what it
needs to draw an input box of the right size without duplicating the
format's rules; and an unknown kind fails safe, showing less rather than
more.
